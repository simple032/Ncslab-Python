# CUDA 仿真：当前进度、预期收益与未来计划

本文面向产品与研发对齐：**做到哪一步**、**能带来什么**、**接下来做什么**。技术细节可与同目录下《CUDA 加速大致流程》《CUDA 仿真路径与流程分析》等文档对照。

---

## 一、当前进度

### 1.1 已完成（可交付、可联调）

| 领域 | 状态说明 |
|------|----------|
| **协议与入口** | 支持在常规仿真 WebSocket 上通过 JSON 字段表达「希望走 CUDA 取向」；另提供专用 WebSocket 路径（便于网关单独配置）。接口说明已写入仓库根部的 WebSocket API 描述文件。 |
| **服务端意愿链路** | 收到「开始仿真」后，能合并「地址类型 + 客户端开关」判断是否进入 CUDA 意愿模式；在独立仿真线程中记录该意愿，并向客户端返回「后端为 CUDA 提示或 CPU」类状态，便于 UI 与联调确认。 |
| **集成接缝** | 提供仅存在于仿真工作线程内的「是否偏好 CUDA」上下文，供后续本地代码或 JNI 读取；日志中会区分 CUDA 提示与普通 CPU worker。 |
| **部署与文档** | 提供可选的 nginx 配置片段；本目录含英文端到端流程说明、中文流程说明（含加速落在时间步数值环节的解释）、性能剖析指引、以及与生成代码 / JNI 集成的边界说明。 |
| **原生概念验证** | `circuit_cuda` 静态库：稳定 C 接口、可选 GPU 构建、无 NVIDIA 环境时可走桩实现；自带微基准用于验证本机 CUDA 工具链与驱动，并演示 CPU 回退行为。 |

### 1.2 尚未完成（与「真在显卡上跑电路仿真」直接相关）

| 领域 | 说明 |
|------|------|
| **生成与编译** | 当前「带 CUDA 意愿」与「不带」在代码生成与编译阶段仍走同一套路径；未自动切换为链接 CUDA 运行库或设备代码的构建配置。 |
| **仿真可执行体** | 主流程中的 `ncslab` 类可执行程序尚未因上述意愿自动启用设备端数值内核；子进程侧也未与 Java 线程内的「偏好 CUDA」自动打通（例如通过环境变量或启动参数，需在启动子进程处接线）。 |
| **热点迁移** | 时间推进循环内的积分、大规模电路/代数块等热点尚未接入 GPU；仓库内 POC 库仅为批处理数值示例，**不替代**完整电路求解。 |

**一句话进度：**「从浏览器到 Java」的 **CUDA 意愿与可观测提示** 已打通；**从数值求解到 GPU** 仍处于设计与接线前阶段，需按下面「未来计划」推进后，用户才能在监控上看到与本次仿真对应的 GPU 负载并感知墙钟加速。

## 二、预期收益

### 2.1 在什么情况下值得做

- **单步或单模型内**存在大量可并行的同质数值工作（例如高维状态、大规模网络、成批支路在同一时刻的计算）。
- **同一模型多次运行**（参数扫描、蒙特卡洛、多工况批处理），适合把一批独立或弱耦合样本打包到设备上。
- CPU 侧剖析已表明瓶颈在**时间步内的数值内核**，而非 WebSocket 推送频率、磁盘 I/O 或极短步长下的通信开销。

### 2.2 预期可量化的收益形态

| 收益 | 说明 |
|------|------|
| **墙钟时间** | 在步长、精度策略可比的前提下，整段仿真或「单位仿真时间」对应的实耗下降。 |
| **吞吐与规模** | 原先在时限内跑不完的大模型或长仿真，在资源允许时能够完成；或单位时间内完成更多次重复仿真。 |
| **资源利用** | 在数值密集阶段，GPU 计算与显存占用与仿真进程对应上升；CPU 可更多承担调度与 I/O。 |

### 2.3 风险与边界（管理预期）

- 小模型、每步极快、或瓶颈在网络/序列化时，**未必**变快，甚至可能因主机与设备间拷贝而变慢。
- 数值路径在 CPU 与 GPU 之间切换时，需约定**精度与一致性**（允许误差或显式双路径回归），避免「变快但结果漂移」。
- 部署依赖 NVIDIA 驱动与运行环境，运维与排障成本高于纯 CPU 方案。

## 三、未来计划（建议顺序）

以下顺序兼顾**风险可控**与**可验证里程碑**；具体排期由项目组根据人力与模型类型调整。

1. **基线剖析**  
   在典型大模型上打开现有 Java / 原生侧剖析开关，确认时间主要花在积分、电路模型、离散更新还是桥接通讯上，避免在错误层级上 GPU 化。

2. **构建与链接路径**  
   在真正产出 `ncslab` 的工程上增加可选 CUDA 构建（或链接本目录 `circuit_cuda` 及后续扩展库），保持无 GPU 机器仍可编译运行（与集成说明中的「可选 CUDA、桩符号」原则一致）。

3. **运行时开关贯通**  
   在启动仿真子进程时传入「本次是否启用 GPU 数值分支」的环境变量或等价机制，并在可执行体入口或求解器初始化处读取，与 Java 侧「偏好 CUDA」对齐。

4. **热点最小闭环**  
   选取一个已剖析确认的热点（例如某一类批量线性代数或成批器件评估），先做设备端内核 + 主机回退 + 与 CPU 参考对比测试，再挂入时间步循环。

5. **产品与回归**  
   固定若干基准模型，对比墙钟、GPU 占用与结果曲线；更新用户可见说明（何时需显卡、如何确认已走 GPU）。

6. **扩展与优化（中长期）**  
   按模块逐步扩大 GPU 覆盖面；视需要引入固定内存、流式多步、与 Java 同进程 JNI 等方案，减少拷贝与同步开销。
